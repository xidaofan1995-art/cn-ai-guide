# 实测方法

把工具放进同一项工作，记录从拿到材料到完成核对要走多少步。

| 记录项 | 怎么做 |
|---|---|
| 测试条件 | 写清工具、模型版本、入口、日期、是否联网和是否用了第三方工具 |
| 共同任务 | 固定输入、提示词、交付格式和合格标准。若工具能力不同，标明差异 |
| 原始产出 | 保存可公开的输入样本、原始回复或导出文件，标出人工改动的位置 |
| 结果质量 | 抽查数字、日期、名称和来源。记录漏项、错误、无法核实和执行失败 |
| 实际投入 | 分开记录工具等待、人工核对和返工。能查到用量时一并注明 |
| 适用条件 | 写明适合哪类任务、哪些步骤需要人工复核、什么情况下应换工具或方法 |

### 怎么读结果

单次跑通能说明这组材料的表现。要比较稳定性，可换一组输入或重复运行。某次结果没跑通，也能帮助判断它目前适不适合你的流程。

## 从实测到选型建议

每个具体场景优先精选 2–5 款有差异的方案，不为凑数推荐。说明默认选择、低成本或其他约束下的替代方案、不适合的场景；把价格、数据接口与模型费用、人工核对和维护成本放在同一判断中，标明核实日期及未实测项。已有优秀低成本方案时优先推荐，不默认自研；自研工具也要接受同题验证。对重复、失效或不再适用的推荐及时更新或撤下。
