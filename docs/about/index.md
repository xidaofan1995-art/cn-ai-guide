# 关于网站

我是桔子哥，这个网站由我个人整理和维护。我做过制造和智能硬件，也在做出海调研。平时遇到一项工作，我会试着用 AI 跑一遍，看看哪些步骤真能省事，哪些地方还得自己回到原始资料核对。我把这些探索写出来，一边靠输出迭代自己的方法，一边给遇到同类问题的朋友留一份可以直接参考的材料。

## 为什么把探索写出来

AI 正在改变很多工作的做法。我刚开始认真研究时，看到过前沿技术、很吸引人的视觉演示，也看过复杂的企业转型方案。回到手上的工作，我关心的是一个更具体的问题：面对这么多说法和工具，我该从哪里入手？培训和教程的质量差异也很大，很容易让人觉得自己又落后了。

我想把散在十几篇文章里的信息，整理成一份能从头读到尾的判断依据。比如讲国产大模型，先用一张图认识主要选择，再给不同模型同一份材料，看看它们怎样填表、算报价、写邮件。单个模型的用法和适用条件，可以顺着总览继续读。

## 我希望这些记录帮到谁

可能是想把表格、汇报做顺手的职场人，也可能是在查海外市场、理展会线索的制造业和外贸朋友。我希望你能找到一个和工作有关的案例，拿走一份材料，按自己的节奏试一遍。我希望熟练使用 AI 能成为更多人掌握的工作能力。省下来的时间，可以多用来理解客户、跟同事沟通，或者把一个判断做得更扎实。

## 怎样选择工具，以及为什么自研

我不打算把这里做成工具导航站或插件商城。每个具体任务优先比较少量有代表性的方案，说明谁适合用、要付出什么成本、什么情况下应换工具。如果已有好用、低成本的方案，我会直接推荐；只有发现真实业务缺口，才考虑开发轻量工具或插件。自研与第三方工具采用同样的验证标准。

知识文章和基础体验优先开放；未来可能对有持续成本或明确专业价值的工具提供付费版本，届时会说明功能边界和价格。是否付费不影响阅读公开内容，也不是推荐某个工具的理由。

## 这里会记录什么

[AI 基础](../basics/index.md)用图表讲清概念和选择，[工具实测](../tools/index.md)记录同一任务在不同工具里的结果，[实战案例](../scenarios/index.md)整理可以带回工作的做法。比如查海关数据，我会把免费入口、商业工具的能力和价格放在一处，再跑一个紧固件案例，帮助你判断哪一步值得花钱。

能公开的原始输出和练习素材会随文放出来。工具、价格和数据口径变了，我会定期回访更新。对我来说，「用 Token 做点有价值的事」就是把一件具体的工作做扎实，顺手把过程分享给别人。
