# 本地部署大模型全攻略：Ollama、LM Studio 怎么选？

**B07 · AI工具与工作流 · 初稿 / 方案研究 · 2026-11-27**

> 本页为公开初稿，可持续修订；作者未补充的个人观点留空，构造案例、AI建议与实际测试分开。动态信息在后续更新前复核。

![数据敏感度、硬件预算与最小离线验证](/images/topics-b07.svg)

## 30秒概览

1. 本地部署是下载已有模型并在自己的设备推理，不是自己训练大模型。
2. 数据不允许外发时，先评估获准的本地环境；硬件或质量达不到要求就暂停，而非私自上传。
3. 不必先买显卡。用现有设备验证一个真实任务，再判断投入。

## 5分钟理解与决策

| 方案 | 数据流向 | 成本结构 | 建议场景 |
| --- | --- | --- | --- |
| 云端网页 | 浏览器 → 服务商 | 订阅或额度 | 允许上传的偶尔问答 |
| 商业 API | 应用 → 服务商 | 用量、集成、重试 | 获准的批量任务 |
| 本地推理 | 应用 → 本机运行环境 | 设备、电力、维护 | 受控环境内的短文本任务、离线需求 |

上表是典型架构而非安全认证。云 API 的数据处理条款随产品而异；本地前端、插件或云回退也可能联网。企业数据管理要求优先。

### Ollama 与 LM Studio

| 维度 | Ollama | LM Studio |
| --- | --- | --- |
| 入门 | CLI 与桌面入口 | 图形界面、CLI |
| 程序调用 | 本地 API | 本地服务 |
| 模型生态 | 模型库及受支持的权重 | 搜索和下载兼容模型 |
| 中文能力 | 取决于模型与量化 | 同左 |
| 硬件 | 取决于模型、上下文及后端 | 同左 |
| 适合人群（建议） | 脚本、Agent及重复任务 | 初次体验、手动比较 |

【已核事实】Ollama 可关闭云模型和联网搜索功能；默认本地服务监听回环地址。LM Studio 下载模型后，聊天、文档问答和本地服务可离线使用；模型下载、更新检查或 runtime 下载仍需要网络。来源：[Ollama FAQ](https://docs.ollama.com/faq)、[LM Studio 离线文档](https://lmstudio.ai/docs/app/offline)（2026-11-27，动态功能需复核）。不做未经实测的速度、中文效果或版本更新频率排名。

### 我的电脑能不能跑？

| 条件 | AI推断：尝试起点 | 约束 |
| --- | --- | --- |
| 8GB 系统内存 | 1–3B 量化、短文本 | 系统与缓存也占内存 |
| 16GB RAM / 统一内存 | 尝试 7–8B Q4、短上下文 | 不保证流畅 |
| 32GB 及以上 | 较大模型或较长上下文 | 需按具体设备实测 |
| 8GB 独立显存 | 尝试合适 7–8B Q4 | 并发或长上下文可能溢出 |

LM Studio 官方建议 Mac 与 Windows 16GB+ RAM，Windows 另建议 4GB+ 独立显存。Mac 需 Apple Silicon、macOS 14+；Windows x64 需 AVX2；Linux 官方以 AppImage 分发并注明 Ubuntu 20.04+，较新发行版兼容性仍须检查。[系统要求](https://lmstudio.ai/docs/app/system-requirements)（2026-11-27，动态信息需复核）。CPU、独立显存和统一内存不可简单相加成高速显存。

## 深度探索：模型文件为何不是全部内存？

Qwen3-8B-GGUF 模型卡标注参数约 8.2B。按十进制 GB 的纯权重理论估算，16 bit 约 16.4 GB，4 bit 约 4.1 GB。这是算术推算，不是实际文件或运行内存。

| 内存组成 | 为什么会增加 |
| --- | --- |
| 权重 | 参数规模、量化方式、混合精度 |
| KV 缓存 | 上下文长度、并发和模型结构 |
| 运行时缓冲 | 推理后端、计算与设备搬运 |
| 系统与应用 | 操作系统、其他任务 |

量化减少存储和内存需求，但可能影响输出质量。[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-8B-GGUF)（2026-11-27，Apache-2.0 标注及版本发布前复核）；[llama.cpp 量化说明](https://github.com/ggml-org/llama.cpp/tree/master/tools/quantize)（方法参考，不是上述换算公式来源）。

### 最小实践：完成一次可复现的离线验证

1. 检查系统、空闲内存、显卡及磁盘；从 [Ollama](https://ollama.com/download) 或 [LM Studio](https://lmstudio.ai/) 官方入口获取应用。
2. 下载支持的本地模型。以 Qwen3-8B-GGUF 为参考，模型卡列有 Q4_K_M 与 Q8_0；如使用 Ollama，可按官方命令格式改用 Q4_K_M。下面是改写示例，非作者亲测，亦非官方原样命令：

```sh
ollama run hf.co/Qwen/Qwen3-8B-GGUF:Q4_K_M
```

3. 先用非敏感样本测试。需要本地隔离时，按 Ollama FAQ 配置 `OLLAMA_NO_CLOUD=1` 或在 server.json 禁用云能力，重启检查日志；检查其他组件是否访问外部服务。
4. 下载完成后断网复测，记录模型版本、量化、上下文、CPU/GPU、内存、首字延迟、生成速度、输出准确性和失败次数。至少准备十条代表性样本，测试前确定质量底线。
5. 若质量不足或延迟不可接受，换更合适模型、缩小任务或在授权前提下改用云端。

断网能验证基本离线推理，不等于完成安全审计。日志、插件、同步文件夹、外部接口与不可信模型来源都需要检查；不要将本地接口裸露在公网。
