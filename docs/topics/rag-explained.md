## 30秒概览
RAG（检索增强生成）像一次开卷考试：先从资料中找相关证据，再让模型依据证据回答。它不是把整个知识库永久训练进模型，也不能保证答案一定正确。

## 5分钟理解与决策
设想公司有两版产品手册。问“保修几年”时，系统应检索有效版本而不是旧版。文档解析、切块、索引、检索、重排和拼接上下文，每个环节都有可能失误。向量检索能找到语义相近内容，关键词检索适合精确料号或术语；混合使用是一种选择。
| 方式 | 优先解决 | 成本结构 | 不适合 |
| --- | --- | --- | --- |
| RAG | 大量且持续变化的资料问答 | 索引、检索、生成 | 无证据仍强制回答 |
| 微调 | 特定任务行为或风格 | 数据整理、训练、评估 | 频繁变更的事实库 |
| 长上下文 | 少量完整文档的综合理解 | 每次输入、延迟、上下文预算 | 持续大规模全量塞入 |

依据[OpenAI检索文档](https://developers.openai.com/api/docs/guides/retrieval)及[文件检索](https://developers.openai.com/api/docs/guides/tools-file-search)（2026-11-27查阅，动态接口需复核），向量库可以用于语义搜索，并可使用元数据过滤。上述对比是定性方法建议。

## 深度探索：为什么会答错
| 失败原因 | 检查方法 |
| --- | --- |
| PDF表格解析损坏 | 对照原始页面与解析文本 |
| 分块拆开条件和结论 | 抽查召回片段是否包含完整含义 |
| 检索旧版 | 元数据标记生效日期、替换失效索引 |
| 召回正确但生成错 | 要求逐条引用并人工复核 |
| 无材料却回答 | 加入无答案样本，检查拒答 |

先用十条有标准答案和几条无答案的问题做验收，再扩大文档库。不能通过检索自动取得未授权文档。本文无实际召回率数据；下一步见[个人RAG知识库实操](./personal-rag.md)，存储职责见[共享知识库](../tools/obsidian-agent-knowledge.md)。
