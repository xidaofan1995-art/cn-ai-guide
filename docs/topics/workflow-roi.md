# AI工作流不是越复杂越好：从一条任务到稳定交付

**B05 · AI工具与工作流 · 初稿 / 方案研究 · 2026-11-27**

> 本页为公开初稿，可持续修订；作者未补充的个人观点留空，构造案例、AI建议与实际测试分开。动态信息在后续更新前复核。

![用频率、节省时间、风险和验收成本决定是否自动化](/images/topics-b05.svg)

## 30秒概览

1. 先有稳定任务，再有自动化；不要先画复杂工作流再找需求。
2. 自动化收益要扣掉核验、返工与维护时间。
3. 风险无法接受时，即使省时间也不应自动执行。

## 5分钟理解与决策

| 任务类型 | 建议 | 验收 |
| --- | --- | --- |
| 偶尔一次的复杂判断 | 对话 + 人决策 | 事实可追溯 |
| 重复且格式固定 | 模板或单 Agent | 必填字段、格式 |
| 多来源、需独立审核 | 多 Agent 分工 | 来源、状态、审核记录 |
| 高风险对外操作 | 草稿自动化 + 人批准 | 权限、批准版本与操作结果 |

用一个可复算的时间账本，而非宣传中的“效率提升百分比”。

**构造样例（非实测）：** 每周整理20份表格，手工每份12分钟，自动化后每份需4分钟人工核验；每周维护30分钟。每周净省时间 = 20 × (12−4) − 30 = 130 分钟。如果搭建需8小时，忽略额外费用及失败损失，回收时间约3.7周。若实际返工使每份核验变成10分钟，净收益只剩10分钟/周，回收期变为48周。这个例子说明核验成本会改变决策。

| 要记录的量 | 口径 |
| --- | --- |
| 任务总次数 | 包括失败与取消 |
| 合格次数 | 达到事先定义的验收标准 |
| 人工时间 | 核验、改稿、故障恢复 |
| 系统费用 | API、订阅增量、服务器 |
| 风险与失败影响 | 误发、漏单、数据丢失等单独记录 |

## 深度探索：给工作流加三条边界

第一，输入输出合同。每个任务必须有可读取的输入、固定字段、明确的交付格式和完成条件；否则模型会自己补齐需求。第二，错误与重试。区分网络超时和业务规则不通过，重试次数有限，人工接管时保留现场。第三，副作用与审批。草稿和正式操作分离，自动发送、删除、付款、正式发布不得因节约时间跳过授权。

可以先选一条每周都做的低风险任务，如整理公开展会名录。用连续若干批次的实际结果评估，不用一次成功当成常态。若失败率、数据质量或核验时间超出事前门槛，就回到手工步骤改输入或验收标准。

**AI建议：** 先自动化明确且重复的部分，让人负责最终判断。新增角色的收益只有在减少净成本或提高验收质量时才成立。
