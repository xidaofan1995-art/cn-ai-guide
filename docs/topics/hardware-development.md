# 智能硬件产品开发全景：从机会发现到上市运营

**C01 · AI×智能硬件 · 初稿 / 方案研究 · 2026-11-27**

> 本页为公开初稿，可持续修订；作者未补充的个人观点留空，构造案例、AI建议与实际测试分开。动态信息在后续更新前复核。

![从阶段交付物、决策门和真实验证理解硬件研发](/images/topics-c01.svg)

## 30秒概览

1. 硬件开发的主线不是文件数量，而是每阶段能否做出进入、返工或停止的决定。
2. 产品定义、供应链、制造和合规要并行考虑，不能到上市前才补。
3. AI 能整理需求与文档，但不能代替实物验证、质量签核和认证。

## 5分钟理解与决策

以下是通用阶段门示意，不是某一企业的内部流程；阶段名称和职责因品类、组织、风险而变。

| 阶段 | 核心决策 | 代表交付物 | 过关证据 |
| --- | --- | --- | --- |
| 机会 | 是否值得研究 | 市场机会简报、需求证据 | 用户痛点、竞品、商业假设 |
| 立项 | 是否投入开发 | MRD、商业测算、初版 PRD | 目标人群、成本与停止条件 |
| 概念 | 方案能否成立 | ID、系统架构、关键器件 | 接口、功耗与风险评估 |
| 设计 | 能否做出符合规格样机 | 结构图、电路、BOM、固件 | 关键设计评审 |
| 工程样机 / EVT | 技术是否可行 | 样机与问题清单 | 实测与缺陷关闭 |
| 设计验证 / DVT | 是否满足设计需求 | 测试计划与报告、合规计划 | 功能、可靠性、安规等按需验证 |
| 生产验证 / PVT | 能否稳定生产 | 工艺、检具、试产记录 | 过程能力、良率、追溯 |
| 上市与运营 | 是否可交付并持续维护 | GTM、包装、售后与反馈台账 | 出货放行及问题闭环 |

阶段门可以重叠。例如认证路径、材料合规、目标市场、试产设备与包装应尽早进入需求和风险计划。具体法规因产品和市场而异，应查目标市场主管机构及实验室；不凭本文判断认证结论。

## 深度探索：每份文档都应支持一次决策

举一个通用、非实测的门窗传感器示例：用户希望关门后可靠提示。PRD 不能只写“蓝牙、纽扣电池、低功耗”，还需给出安装约束、离线表现、告警时延、续航测试条件、温度范围及误报验收。结构、射频、固件和供应商要根据同一需求分解。样机如果能发消息却无法满足续航目标，应调整功耗或电池设计，而不是仅凭页面展示宣布开发完成。

| AI可以协助 | 必须由人或真实系统完成 |
| --- | --- |
| 归纳评论、竞品规格、MRD草案 | 用户访谈、真实需求证据 |
| 比较方案、初步 BOM、风险清单 | 工程评审、选型确认、样品 |
| 测试计划和问题归类 | 实验室测试、量产良率、认证 |
| 上市材料、售后问题统计 | 出货放行、对客承诺、质量责任 |

阶段门应有明确的决策人、条件、证据与复测责任；记录未关闭风险而不是把空白文档算作完成。原型和模拟不等于实物交付，任何 AI 生成图、效果图或推算只能作为设计输入。
